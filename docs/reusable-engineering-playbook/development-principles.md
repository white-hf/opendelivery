# 开发原则

- 先更新需求/设计/迭代文档，再写代码；任何行为变化都要有验收标准。
- 命令侧使用 ORM Entity + Repository；简单查询使用 Projection/JPQL；聚合、空间和大批量查询使用独立 Query Repository。
- SQL 不写在 Controller 或领域实体中；保留 SQL 时必须说明 escape-hatch 原因。
- 所有写操作考虑幂等键、并发版本、权限、审计和重试后的重复执行。
- API 保持稳定的错误码、响应信封、分页和兼容策略；破坏性变更必须版本化或提供迁移窗口。
- 外部输入先校验、规范化，再进入领域模型；禁止把供应商字段直接扩散到内部核心模型。
- 配置和密钥来自环境或密钥管理系统，日志禁止输出令牌、密码和敏感载荷。
