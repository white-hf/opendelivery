# Documentation Standard

| Artifact | Purpose | Update |
|---|---|---|
| PRD | Users, workflow, scope, non-goals, acceptance | Before product behavior changes |
| System design | Modules, dependencies, interfaces, data flows, mechanisms | Before architecture changes |
| Data/API contract | Tables, fields, indexes, requests, responses, compatibility | Before data or API changes |
| Iteration plan | Goal, tasks, DoD, risks, dependencies | Before coding; mark REVIEWED |
| Test plan/evidence | Scenarios, data, commands, results, baselines | During development and acceptance |
| Execution summary | Actual changes, evidence, residual work, rollback | At iteration close |
| ADR | Important technical choices and trade-offs | When a decision is made |

Keep documents concise, actionable, and measurable. Separate business and technical documents, keep important artifacts bilingual, and link only to the current valid version.
